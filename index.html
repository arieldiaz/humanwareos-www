02 — The inversion

We used to work for the tools.

For most of computing the deal was that you learn the language, the terminal, the metaphor. Now the computers speak ours.

Which should have been the end of it. Instead, directing work turned out to be harder than doing it: more decisions, more context at once, more threads than one person can track.

Conductor and Superset handled parallel coding well, and nothing past it. Paperclip had the best mental model going — agents as skills, permissions, and context, routed like an org chart — but spun up too much too fast. A workflow in Notion was all friction.

The coordination layer already existed.

Slack spent a decade refining how people actually work. Threads. Notifications that mean something. Channels as context. Integrations with anything.

So the interface is not new. The agents move in behind it.

03 — Why this is opinionated

One line in someone else's config made me stop and build my own.

“Never ask a human to do what an agent can do.”

Found in an agent config · the inverse of Agent Smith's line
That premiseThe human is overhead. Route around them.
This oneThe human is the point. Stay close to the decisions, the sequencing, the fidelity.

Both systems can run the same models on the same machine. Only one of them is trying to need you less every week.

You read a thread's whole state off the reactions, without opening it.

The status language — five states, nothing else

🔄In process

On the agent, actively moving.

❓Clarify

On you. You owe an answer.

✋Act

On you. Only your hands can do it.

🗓️Scheduled

Comes back at a set time.

✅Done

You confirmed the outcome.

No generic "blocked." Dated means scheduled; undated means still the agent's problem.
